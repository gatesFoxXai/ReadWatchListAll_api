## 範例：使用 Python + Google Cloud TTS

```bash
# 1. 安裝依賴
pip install google-cloud-texttospeech

# 2. 下載服務帳戶金鑰並設置環境變數
export GOOGLE_APPLICATION_CREDENTIALS="/path/to/your/key.json"
```

```python
from google.cloud import texttospeech

def synthesize_text(text, output_file="output.mp3"):
    client = texttospeech.TextToSpeechClient()

    # 設定輸入文字
    synthesis_input = texttospeech.SynthesisInput(text=text)

    # 選擇語音語言與聲音 (此例為英語美式)
    voice = texttospeech.VoiceSelectionParams(
        language_code="en-US",
        ssml_gender=texttospeech.SsmlVoiceGender.NEUTRAL,
    )

    # 設定音頻格式
    audio_config = texttospeech.AudioConfig(
        audio_encoding=texttospeech.AudioEncoding.MP3
    )

    # 進行合成
    response = client.synthesize_speech(
        input=synthesis_input,
        voice=voice,
        audio_config=audio_config,
    )

    # 儲存檔案
    with open(output_file, "wb") as out:
        out.write(response.audio_content)
    print(f"已儲存為 {output_file}")

# 測試
synthesize_text("Hello, world!")
```

### 範例（Python + Paramiko）

```bash

sudo apt install -y python3-venv python3-pip
python3 -m venv venv
```

```python
# mac_agent.py
import os
import openai
import paramiko

# 1️⃣ OpenAI API Key
openai.api_key = os.getenv("OPENAI_API_KEY")

# 2️⃣ SSH 設定
HOST = "mac-mini.local"
PORT = 22
USER = "your_user"
KEY_FILE = "/path/to/your/id_rsa"  # 或直接輸入密碼

def ask_gpt(question: str) -> str:
    resp = openai.ChatCompletion.create(
        model="gpt-4o-mini",
        messages=[{"role":"user","content":question}],
    )
    return resp.choices[0].message.content.strip()

def run_remote(cmd: str):
    client = paramiko.SSHClient()
    client.set_missing_host_key_policy(paramiko.AutoAddPolicy())
    client.connect(hostname=HOST, port=PORT, username=USER, key_filename=KEY_FILE)
    stdin, stdout, stderr = client.exec_command(cmd)
    output = stdout.read().decode()
    client.close()
    return output

if __name__ == "__main__":
    user_query = "請在 mac mini 上重新啟動 nginx。"
    gpt_response = ask_gpt(user_query)
    # 假設 GPT 回覆為： "sudo systemctl restart nginx"
    print(f"GPT 建議的指令：{gpt_response}")
    print("執行結果：")
    print(run_remote(gpt_response))
```

> **安全提示**
> - **私鑰**不要直接放在程式碼內部，使用環境變數或是 `ssh-agent`。
> - 如果是多台機器，建議把 SSH 主機 key 存成 dict，或是利用 `fabric` 的 `Connection` 來管理。

## 3️⃣ 如何使用 GPT‑4o 進行程式碼生成？

1. **取得 API Key**（OpenAI 或 Azure）
   ```bash
   export OPENAI_API_KEY="your_api_key_here"
   ```

2. **簡單範例（Python）**

   ```python
   import openai

   openai.api_key = os.getenv("OPENAI_API_KEY")

   def generate_code(prompt, language="python"):
       response = openai.ChatCompletion.create(
           model="gpt-4o-mini",   # 或 gpt-4o、gpt-4-turbo
   ```

## GPT‑4 vs GPT‑4o (及 GPT‑4o‑mini)

| 指標 | GPT‑4 (正式版) | GPT‑4o / GPT‑4o‑mini |
|------|---------------|---------------------|
| **模型架構** | 基於 **4‑billion‑parameter** “Claude‑style” transformer, 8‑k context window (約 32 k token) | 同樣的 transformer core，但經過**量化、蒸餾、分布式優化**，專為速度與成本優化 |
| **速度** | **慢**（約 1–2 秒/回應，依照 OpenAI 的“turbo”標準） | **快**（約 0.3–0.5 秒/回應，約 4‑5× faster） |
| **成本** | **高**（≈ $0.03/1k prompt + $0.06/1k completion） | **低**（≈ $0.003/1k prompt + $0.006/1k completion） |
| **上下文長度** | 8k tokens | 32k tokens（大多數情況下） |
| **多模態** | **不支援** | **支援**（文字+影像、音訊輸入） |
| **程式碼生成** | 可以，但不如 GPT‑4o 專門化 | 專為程式碼生成（尤其是 “quick‑response” 風格）優化，加入了 “best‑practice” 產出 |
| **可調參** | `temperature`, `top_p`, `max_tokens`, `stop` 等 | 同樣，但多數場景建議 `temperature=0.2–0.3` 以保持可預測性 |
| **主要使用案例** | 複雜對話、長篇內容生成、深度分析 | 快速原型、程式碼生成、低成本長文本、嵌入式應用 |

> **簡言之**：GPT‑4o 是“更快、更省錢、更長上下文”的 GPT‑4 變體。若你需要大量長文本、影像輸入或高效代碼生成，GPT‑4o（或 GPT‑4o‑mini）會是首選。

## Codex：從單獨模型到 GPT‑4o 的「代理」功能

| 版本 | Codex 狀態 | 主要功能 |
|------|------------|-----------|
| **Codex (2021‑2023)** | **單一模型**：`codex-davinci`, `codex-codex` 等 | 專為程式碼生成（Python, JavaScript,Go, …） |
| **GPT‑4 (正式版)** | **無 Codex 代理**（但可產生程式碼） | 可透過 `ChatCompletion` 產生程式碼，但不具備 Codex‑專用的“prompt‑to‑code” API 參數 |
| **GPT‑4o / GPT‑4o‑mini** | **整合 Codex 能力** | 內建 **code‑generation 模式**：在提示中加上`["role":"user","content":"寫 …"]` 就能直接得到高質量程式碼，且支援多語言、最佳實踐建議 |

### 代理功能說明

- **Codex 代理**：舊 Codex API 允許你直接把自然語言提示交給模型，返回純程式碼（通常以 `text-davinci-002` 為基礎，支援 `prompt` 參數）。
- **GPT‑4o 的代理**：現在所有「程式碼生成」功能都被整合進 GPT‑4o。你不需要再呼叫一個單獨的 Codex endpoint；只要用GPT‑4o（或 GPT‑4o‑mini）即可得到相同甚至更好的程式碼。
- **「代理」的意義**：如果你想要把 Codex 的「程式碼生成」行為包裝成一個 API 或服務，最簡單的方法是：

  1. 在你的後端（例如 FastAPI）呼叫 `openai.ChatCompletion`，使用 `model="gpt-4o-mini"`。
  2. 在提示中加入 **程式碼上下文**（例如說 “請生成一個 Python 函式”），並選擇 `temperature=0.2` 以保持一致性。
  3. 直接把返回的程式碼送回前端或寫進檔案。

> 這相當於在 GPT‑4o 上搭建一個「Codex‑代理」——它不再是獨立模型，而是 GPT‑4o 自己的內建能力。

---

## 什麼時候選擇 GPT‑4 vs GPT‑4o

| 場景 | 推薦模型 |
|------|----------|
| **複雜、長篇對話**（法律、醫學、科研論文等） | GPT‑4 (正式版) 或 GPT‑4‑Turbo |
| **影像/音訊輸入** | GPT‑4o |
| **代碼生成**（快速原型、單元測試、自動化腳本） | GPT‑4o‑mini 或 GPT‑4o |
| **成本敏感、需高吞吐量** | GPT‑4o |
| **需要 8k 上下文窗口、對話一致性** | GPT‑4 |

---

## 小結

| 問題 | 答案 |
|------|------|
| **GPT‑4 與 GPT‑4o 的差異** | GPT‑4o 更快、低成本、32k token 上下文、支援影像/音訊，多模態；GPT‑4 正式版更適合深度、長對話。 |
| **是否內含 Codex 代理功能** | **是**：Codex 的程式碼生成能力已被內建在 GPT‑4o（尤其是 `gpt-4o-mini`）中。沒有獨立的 Codex API 了，但你可以直接使用 GPT‑4o 的 `ChatCompletion` 產生程式碼。 |

> 如果你還想使用舊 Codex 模型（在本地或自建環境），需要自行部署，OpenAI 官方已停止對 Codex API 的支援。對大多數開發者而言，直接切換到 GPT‑4o 或 GPT‑4 Turbo 就能得到更好的程式碼產出與成本效益。

### 只要一行代碼就能把 Python 的 `dict`（或任何 JSON‑serialisable 物件）印成「漂亮」的 JSON：

```python
import json

# 你的 JSON 物件（實際上就是一個 dict / list / str / int 等）
data = {
    "name": "Alice",
    "age": 30,
    "skills": ["Python", "Data Science", "Machine Learning"],
    "address": {"city": "Taipei", "zip": "100"},
}

print(json.dumps(data, indent=4, sort_keys=True, ensure_ascii=False))
```

#### 參數說明

| 參數 | 作用 | 範例 |
|------|------|------|
| `indent` | 每層縮排多少個空格（`None` 表示不縮排，`2`/`4` 常見） | `indent=4` → 4 個空格 |
| `sort_keys` | 是否將字典鍵字順序化（有助於可重複性） | `sort_keys=True` |
| `ensure_ascii` | `False` 允許印出 Unicode 字符（中文、日文等） | `ensure_ascii=False` |
| `separators` | 指定 `item_separator` 與 `key_separator`，預設 `(',', ': ')` | `separators=(',', ': ')` 可以省略空
格 |

> **小技巧**
> 若你只想快速「美化」一個已經是字串的 JSON，可直接 `on.dumps(json.loads(json_str), indent=4))`。

## 另一種方式：`pprint` 模組

```python
from pprint import pprint

pprint(data, width=80, sort_dicts=True)
```

`pprint` 在某些情況下更容易閱讀，但它不是合法的 JSON 字串（例如使用單引號）。如果你需要真正的 JSON 字串，還是用
`json.dumps`。

### 例子：完整腳本

```python
#!/usr/bin/env python3
import json
import sys

def main():
    # 假設你有一個 JSON 物件，或從文件、API 取得
    data = {"foo": "bar", "numbers": [1, 2, 3], "nested": {"a": True, "b": None}}

    # 將它格式化成美觀的 JSON 並直接印到 stdout
    print(json.dumps(data, indent=4, sort_keys=True, ensure_ascii=False))

if __name__ == "__main__":
    main()
```

```
    "nested": {
        "a": true,
        "b": null
    },
    "numbers": [
        1,
        2,
        3
    ]
}
```

edge-tts 是一個 Python 模組，它允許您在 Python 程式碼中使用 Microsoft Edge 的線上文字轉語音服務，或使用提供的 edge-tts 或 edge-playback 命令。

安裝
要安裝 edge-tts，請執行以下命令：

$ pip install edge-tts

如果您只想使用 edge-tts 和 edge-playback 指令，建議使用 pipx：

$ pipx install edge-tts

用法
基本用法

如果您想使用 edge-tts 命令，只需執行以下命令：

$ edge-tts --text "Hello, world!" --write-media hello.mp3 --write-subtitles hello.srt

如果您希望立即播放帶有字幕的文本，可以使用 edge-playback 命令：

$ edge-playback --text "Hello, world!"

請注意，除 Windows 系統外，edge-playback 需要安裝 mpv 命令列播放器。

所有 edge-tts 指令可與 edge-playback 搭配使用，但 `--write-media`、`--write-subtitles` 和 `--list-voices` 選項除外。

變更語音

自訂 SSML

由於 Microsoft 禁止使用任何無法由 Microsoft Edge 本身產生的 SSML，因此已移除自訂 SSML 的支援。這意味著所有自訂 SSML 有用的場景都無法獲得支持，因為該服務僅允許使用一個 <voice> 標籤，且該標籤內只能包含一個 <prosody> 標籤。任何可在 <prosody> 標籤中使用的自訂選項都已可透過庫或命令列取得。

變更語速、音量和音調

您可以使用 --rate、--volume 和 --pitch 選項來變更產生語音的語速、音量和音調。使用負值時，您需要使用 --[option]=-50% 而不是 --[option] -50%，以避免該選項被解釋為命令列選項。

$ edge-tts --rate=-50% --text "Hello, world!" --write-media hello_with_rate_lowered.mp3 --write-subtitles hello_with_rate_lowered.srt

$ edge-tts --volume=-50% --text "Hello, world!" --write-media hello_with_volume_lowered.mp3 --write-subtitles hello_with_volume_lowered.srt

$ edge-tts --pitch=-50Hz --text "Hello, world!" --write-media hello_with_pitch_lowered.mp3 --write-subtitles hello_with_pitch_lowered.srt
